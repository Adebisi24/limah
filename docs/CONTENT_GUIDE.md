# Adding content to Nest Nabber

1. Open https://nest-nabber-limah.sanity.studio/ and sign in to Sanity. The local editor is also available at http://localhost:3333 while `npm run studio` is running.
2. Edit **My author profile** once with your public name, bio, and portrait. Every article uses this single profile automatically. Create room documents as needed; use Bedroom, Living Room, Kitchen, and Bathroom for the current hubs. Styles remain reusable tags; select their matching collections when an article belongs on a style page.
3. Add reusable products with an image, exact/similar relationship, and up to three retailer links. Enter a price only after checking it; otherwise the site uses “Check price at [retailer]”. Product links must use HTTP or HTTPS.
4. Create an Article and select one of the six article formats. Set its title, slug, excerpt, room, publication date, and **Collections**. Choose the broad parent and every specific topic that applies—for example, `Home`, `Home Organization`, and `Bedroom Organization`. Your author profile is attached automatically. A cover image is optional for text-only posts. Add article text in the rich-text field.
5. Inspiration articles use the Ideas array for each image, heading, and paragraph. Buying Guides use Guide Sections for advice, checklists, and diagrams/images. Shopping formats use product references plus article-specific editorial notes. Best Products includes methodology and pros/cons; Shopping Finds hides those extra details on the website.
6. Select preferred related articles if needed. Otherwise the site chooses other articles of the relevant format, prioritizing the same room. It shows only available content and never duplicates a card just to fill a count. Maximums follow the approved layouts: 12/8 or 8 looks. Plan Your Room accepts up to eight article references and always renders text-only links.
7. Open Site Settings to select the homepage feature and latest stories, brand text, description, and contact address.
8. Publish the documents. Sanity automatically starts a Cloudflare production rebuild. Wait for that deployment to succeed, then refresh https://limah.pages.dev/ to see the changes. Draft edits do not trigger builds or appear publicly.

Use **Articles by collection** in the Studio sidebar to browse the full library under Home, Interior Design, Home Organization, and Shopping. An article can belong to several related collections without being duplicated.

Sanity is the source for all website articles and products. Edit imported articles under **Content → Introduction / article text**: paragraphs, links, headings, images, and captions are editable there. The ten originally untitled posts use titles derived from their headings. Posts without supplied images remain text-only. There is no ongoing WordPress synchronization.

Original project articles use **Content → Designed article sections**; preserve their order to keep the layout. These sections take precedence over introduction text. Overlapping imports use rich text instead, with old designed sections removed so edits display correctly. Edit prices and affiliate links under **Products → Retailers**. Unpublished or deleted articles disappear after the next successful build; local demo articles are never added back.

Cloudflare builds automatically use Sanity; an older `CONTENT_MODE=demo` variable is ignored by the Next.js configuration. The default project is `9tacupln`, dataset `production`. Set `SITE_URL` to the deployed website URL for canonical links and indexing. The Sanity webhook **Nest Nabber - Cloudflare publish** calls the Cloudflare **sanity-publish** deploy hook for branch `main`. It handles creation, updates, and deletion of published articles, products, authors, rooms, styles, and site settings. Drafts and release versions are excluded. The hook URL is private and is not stored in Git or browser code.

If a published change is missing, check the webhook delivery log in Sanity and the latest deployment under Cloudflare → Workers & Pages → limah → Deployments. A failed build leaves the previous successful website online. A successful webhook delivery means the build was requested; wait for Cloudflare to finish deploying before checking the website.

No reader accounts are used. Saved articles and likes remain on each browser. Newsletter signup remains inactive until a sending service is connected.
